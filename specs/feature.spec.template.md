# Feature spec template

Copy this file into `specs/features/` as `SAN-<issue>-<slug>.spec.md` when a Phase 1+ feature is about to be built and its behaviour needs to be agreed before coding. Delete sections that don't apply — don't leave placeholders.

## Linear issue

SAN-XXXX

## Problem

What visitor/admin/agent problem does this solve? One paragraph.

## Requirements

Reference BRD FR IDs where they exist. List concrete, testable requirements — not implementation detail.

## Out of scope

What this feature explicitly does not do (prevents scope creep and re-litigating later).

## Data model changes

New tables/columns, or "none".

## API changes

New/changed endpoints, or "none".

## Acceptance criteria

Given / When / Then, following the BRD's style (§16). At least one happy path and one edge case.
